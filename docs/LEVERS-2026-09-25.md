# The levers of 2026-09-24/25 — what each one is, costs and bought

Integrated on main the night before the pre-test (2026-09-25 afternoon; demo
2026-09-26). Goal: process two live 4K cameras (H.265, 15 fps, GOP 15) at or
above camera rate without missing a PERSON, and make the duplicate-review
queue trustworthy on Punjab wedding footage.

**Every throughput lever is OFF by default, and OFF is today's pipeline,
pinned by a test** — the ingest worker and its six-field `/frame`, the
runner's call sequence against a fixture captured from 421210b, the stage
services' fp32 providers and byte-identical pre-processing. The review
set-asides (clothes, head, beard) default ON because they remove nothing from
a count: a set-aside pair only leaves the ranked queue, stays listed in
`setAside`, and is still mergeable.

Baseline the levers are measured against (the .94 box, 2026-09-24): one 4K
camera, whole-frame SCRFD-10G, ~200 ms/frame with every stage serial in the
runner loop — reference run d02-…-f0bfc5 processed 15,076 frames at 3.9 fps
in lockstep.

## The knobs

Env knobs reach their container through the `${X-}` pattern in
docker-compose.yml (unset and empty both mean the service default), and each
is readable back from the running service — the column says where.

### Ingest — L1 motion gate + bounded live buffer, L6 hardware decode

| knob | default | what it does | what it costs / bought | read back |
|---|---|---|---|---|
| `INGEST_MOTION_GATE` | `0` | Publish a frame only if its ~1/8-scale luma changed against the last PUBLISHED frame (each small frame normalised by its own mean and std, so a lighting step or DJ flash is not motion), or the keepalive is due. Per run: `source.motionGate` on `POST /runs`, forwarded to ingest `/open`. | cpu decode + gate 56.4 ms CPU per 4K frame vs 34.2 ungated (every frame must be retrieved); nvdec + gate 30.4 ms with `INGEST_CV_THREADS=1`. On the Sharon placement the default threshold skips **1 frame in 15,077** — calibrate per placement first. | ingest `/health` `knobs`, `capture.counters`; run results `framesSkippedNoMotion` |
| `INGEST_MOTION_MIN_FRAC` | `0.002` | Fraction of small-luma pixels that must change to count as motion. | D02 replay (15,076 frames, 78 identities): 0.01 skips 6.6% of frames, 1.5% of kept-face frames, 0 identities lost; **0.02 skips 20.3% / 6.6% / 0 lost** (worst guest keeps 74% of his frames); 0.05 skips 43.1% and loses one identity. `services/ingest/scripts/gate_replay.py` calibrates a placement. | ingest `/health` |
| `INGEST_MOTION_PIXEL_THR` | `0.08` | How far one small pixel must move, in units of that frame's own luma std. | — | ingest `/health` |
| `INGEST_MOTION_KEEPALIVE_S` | `1.0` | Longest a still scene goes unpublished (footage seconds for files, wall seconds for cameras), so trackers and stall detection stay alive. | — | ingest `/health` |
| `INGEST_BUFFER_S` | `0` | `0` = today's newest-frame slot. `> 0` = a FIFO of up to that many seconds of published frames for live and paced sources; `GET /frame` then dequeues the OLDEST. Lockstep never queues. Per run: `source.bufferS`. | nvdec, 10 s: backlogMax 150 NV12 frames = 1.87 GB per camera; cpu path hits the 2048 MiB cap at 5.7 s. Dropped frames are counted, never silent. | ingest `/health`; results `framesDroppedLive`, `ingestBacklogMax` |
| `INGEST_BUFFER_MB` | `2048` | Hard cap on the FIFO, oldest dropped first (the newest is never the one dropped). | — | ingest `/health` |
| `INGEST_DECODER` | `cpu` | `cpu` = today's cv2 path; `nvdec` / `vaapi` / `ffmpeg` = an ffmpeg subprocess sending NV12 over a socketpair; BGR conversion only for frames actually served. Needs the `heco-ingest:hwdec` image and `docker-compose.hwdec.yml`. A decoder that cannot start falls back to cpu LOUDLY (stderr + `/health device.error`). | NVDEC decode 1.3 ms/frame; nvdec + `INGEST_CV_THREADS=1`: 25.5 ms CPU per 4K frame vs 33.5 for cpu. Two nvdec cameras with the gate: 0.83 cores for both at 14.95 fps each. **VA-API cannot work on the .94 box**: its WSL kernel lacks `CONFIG_UDMABUF` (vgem is loaded and persisted, which is necessary, not sufficient). | ingest `/health` `device {requested, active, error}` |
| `INGEST_CV_THREADS` | unset (a thread per core) | OpenCV pool size, process-wide, once at startup. | `1` cut nvdec + gate from 45.4 to 30.4 ms CPU per 4K frame on the 28-thread box, same latency. | ingest `/health` `knobs.cvThreads` |
| `INGEST_LIVE_TIMEOUT_S` | `0` (off) | A LIVE source on any decoder: a read that waits this long is a dead stream — its stale frame dropped, the source reopened (cv2: open/read timeouts; ffmpeg: a socket read watchdog, ffmpeg's own timeouts moved to 2x). **Set `10` for live cameras.** | A camera that goes silent with its TCP open: cv2 today took ~90 s to reconnect (60 s without a new frame — past the runner's 45 s stall window, the run fails); nvdec 23 s. With `10`: both decoders back 12.7 s into the stall (laptop, fake RTSP camera). Also catches a decoder that hangs without exiting. | ingest `/health` `knobs.liveTimeoutS`, `capture.live {stalls, reconnects, reconnectFailures}`, `device.error` while down |
| `HECO_HWDEC_TAG` | `hwdec` | Image tag the hwdec overlay runs (`heco-ingest:${HECO_HWDEC_TAG}`), like `HECO_CUDA_TAG`. | — | — |

With a lever armed `/frame` also carries `motion` (null when not measured),
`backlog`, `skipped` (null with the gate off), `dropped` and `captured`; the
runner carries them into status, results and notes as `framesCaptured`,
`framesSkippedNoMotion`, `framesDroppedLive`, `ingestBacklogMax` — present
only when measured (absent is not zero), and the console's "What this run
looked at" card reads them.

### Models — L2 TensorRT fp16, L5 SCRFD-2.5G, embed batching

| knob | default | what it does | what it costs / bought | read back |
|---|---|---|---|---|
| `HECO_DEVICE=TRT` (alias `TENSORRT`) | `CPU` (the demo sets `CUDA`) | persons / faces / embed (and genderage) run TensorRT fp16 → CUDA → CPU; engine + timing cache under `HECO_TRT_CACHE`, 2 GiB workspace. Set by `docker-compose.trt.yml`. | session.run on 8 real 4K frames: YOLOX-s 7.1 → 3.3 ms, SCRFD-10G 1472x832 20.0 → 5.4 ms, ArcFace 23.3 → 8.6 ms per 5.5-face frame; parity, re-measured on 40 frames: no person or face gained or lost at score 0.5 or 0.7 (268 persons, 243 faces), 0 gender flips, age within 0.17 y; person IoU p1 0.987 (min 0.93, a partial person), face IoU min 0.987, landmarks ≤ 0.30 px, ArcFace cosine min 0.9997 (0.9999 for faces ≥ 56 px), feature norm within 1.1% — the tails are small or half-hidden subjects. **Cold engine builds** at first `/health`: YOLOX-s 157 s, SCRFD 34 s, ArcFace 32–38 s, genderage 20 s; cached starts < 1 s. VRAM ≈ 0.77 GB per stack. | stage `/health` `device {requested, active, trt}` (`trt: null` = TensorRT did not come up) |
| `HECO_TRT_CACHE` | `/srv/trt-cache` | Engine + timing cache dir; the overlay puts it on a per-project volume. Engines sit in `<dir>/<sha256[:12] of the weights>`, so new weights are a new engine (a cold build) whatever the file is called — the EP's own engine name ignores the weights, and before this a same-architecture swap or an in-place re-fetch ran the OLD engine (measured). `FACES_SCRFD_INPUT` and `EMBED_BATCH` are cold builds too. The first start after the re-key builds every engine once. | — | `device.trt.engineCache` (the hash directory) |
| `EMBED_BATCH` | off | `1` = a request's faces in one `session.run` (chunks of 16), attributes likewise. | CUDA embed 23.3 → 11.6 ms and attributes 6.1 → 1.7 ms per frame; TRT 3.7 + 0.9 ms. Vectors match per-face at cosine ≥ 0.999999. | embed `/health` `knobs.batch {requested, active, max}` |
| `FACES_MODEL=scrfd_2.5g_kps.onnx` | `scrfd_10g_kps.onnx` | L5 lighter face detector (weight installed on both box trees; three draft console profiles `…-live-scrfd-2-5g-…`). | 2–2.5x cheaper than 10G, and it loses about **1 in 5 countable face sightings** (≥ 56 px) at score 0.7 — 40 frames of the bench clip: 7 of 10G's 34 at 640, 7 of 41 at 1472x832, faces up to 242 px, every one scored 0.70–0.83 by 10G (2.5G scores the same faces lower, so the shared 0.7 floor cuts them). Do not run it live until its own `FACES_SCRFD_SCORE_MIN` is calibrated on labelled footage. **On TRT, 10G at 1472x832 (5.3 ms) beats 2.5G on CUDA — prefer TRT + 10G.** | faces `/health` `model` |
| `FACES_SCRFD_INPUT` | unset = `640` square | Existing knob, passed through `docker-compose.gpumax.yml`. | **All three box stacks run 640**: on a 4K whole frame faces under 96 px cannot be detected (42 px at 1472x832). With TRT, 10G at 1472x832 costs less than today's fp32 at 640. Recommended together with TRT. | faces `/health` |

### Runner — L3 stage overlap, L4 face cadence, L7 face search region

| knob | default | what it does | what it costs / bought | read back |
|---|---|---|---|---|
| `HECO_PIPELINE_OVERLAP` | `0` | One worker thread fetches frame k+1 and runs its detection (persons; faces too when the search needs no tracks — whole frame or region) while the loop decides frame k. At most one frame ahead; tracker, match, locks, co-presence, ledger and taps stay on the loop thread in frame order. | Synthetic harness (persons 30, faces 70, embed 20, match 5 ms): whole frame 7.7 → 9.5 fps, crops 7.5 → 10.2 fps. Not yet measured on the box. Under overlap a frame record's stage ms are per-stage WORK, not wall time. | runner `/health` `knobs`; run config `levers.pipelineOverlap`; board `count/detectWaitMs` |
| `HECO_PARALLEL_DETECT` | `0` | Persons and the whole-frame or region face search for one frame issued side by side. No effect on crops. | Whole frame 7.7 → 9.5 fps alone, **13.8 fps (1.79x) with the overlap** in the harness. | `levers.parallelDetect` |
| `HECO_FACE_CADENCE` | `0` | Skip a frame's face `/detect` when there is ≥ 1 person box, every box is covered one-to-one (IoU ≥ 0.5) by a SETTLED track (identity lock refreshed by a comfortable match within `faceReverifyIntervalS`), and less than the max gap has passed since the last search. A body a detections zone drops still holds the search open while its head point is outside every zone (its face can still count — the verifier's repro counted 1 of 2 guests without this). On crops a search it lets through is a full pass (the re-verify gate had emptied the max-gap searches). Skipped frames still track and still assert track presence. | Scripted run: 6 of 11 frames skipped, unique unchanged. **Skips nothing while `HECO_FACE_REVERIFY_INTERVAL_S` is 0** (warned at run start). | `levers.faceCadence`; results `faceDetectSkippedSettled` |
| `HECO_FACE_CADENCE_MAX_GAP_S` | `1.0` | Longest stretch of frame time (`tMs`) without a face search — footage time on a live camera, but PROCESSING time on a lockstep file replay (ingest stamps wall time since /open), so a replay faster than real time skips more footage per gap (20 fps lockstep: 1.0 s ≈ 1.33 s of footage) and a pre-test's skip counts do not transfer 1:1 to live. Bench it paced. | — | runner `/health` |
| `HECO_FACE_REVERIFY_INTERVAL_S` | `0` | Existing knob, newly plumbed through compose: the crop path's re-verify saving and the cadence's "settled" window. Pair 2–3 s with the cadence (or the run's quality profile `faceReverifyIntervalS`). | — | runner `/health` |
| `faceRegion` on `POST /runs` | null | `{x,y,w,h}` normalised, inside the frame, ≥ 5% a side (else 422). Faces searched ONLY there, as one native-resolution crop, whatever `HECO_FACES_WHOLE_FRAME` says; persons and tracker stay whole-frame. The console stores it per camera (zone editor) and forwards it only to a pipeline whose manifest declares `capabilities.faceRegion: true` (pipeline.json does). | Sharon frames, SCRFD-10G 1472x832: letterbox scale 0.383 → 0.767; the region found 34 faces where the whole frame found 18 (all 21 extras 7–28 px, under the 56 px floor), and lost 2 real low-quality guests (43x50 under a dark patka, 45x42 in shadow) that the whole frame found. **Not a recall superset — price it on the box before a paying event.** | run config `faceRegion`; results `faceRegionUnplaced` |
| `source.motionGate` / `source.bufferS` on `POST /runs` | absent | Per-run overrides of the ingest L1 knobs, forwarded to ingest `/open` (absent = the ingest env). | — | ingest `/health` `capture.knobs` |

### Shared-memory branch only (`shared-memory-transport`)

`HECO_FRAMES_DIR`, `HECO_FRAMES_KEEP` (8; floored at 4 — overlap with
prefetch holds three frames in flight), `HECO_FRAMES_TMPFS_SIZE` (1g),
`HECO_FRAMES_REF_ONLY` (off) — see docs/SHARED-MEMORY-BRANCH.md on that
branch. Every lever above works on refs there: frames are written when taken,
numbered by write (a gate's seq gaps cannot retire a frame still in flight),
cleared with the run; every detector path carries the ref; the runner mounts
the frames to cut its own descriptors under ref-only.

## Turning a lever on for a stack

The scripts export nothing for the levers: an unset variable is the service
default, off. Set it in the environment of the script, per invocation:

    # camera A, overlap + parallel detect + NVDEC with one OpenCV thread, and a
    # silent camera reopened after 10 s whatever decoder ends up running
    HECO_PIPELINE_OVERLAP=1 HECO_PARALLEL_DETECT=1 \
    HECO_HWDEC=1 INGEST_DECODER=nvdec INGEST_CV_THREADS=1 INGEST_LIVE_TIMEOUT_S=10 \
      ./scripts/demo-up.sh a

    # TensorRT (needs :cuda images built WITH it: HECO_TRT=1 ./scripts/build-images.sh)
    HECO_TRT=1 FACES_SCRFD_INPUT=1472x832 ./scripts/demo-up.sh both

    # the face cadence needs its settledness window
    HECO_FACE_CADENCE=1 HECO_FACE_REVERIFY_INTERVAL_S=2.5 ./scripts/demo-up.sh a

    ./scripts/demo-up.sh status     # every knob as the CONTAINERS hold it, device truth

`HECO_TRT=1` appends `docker-compose.trt.yml` (last); `HECO_HWDEC=1` appends
`docker-compose.hwdec.yml`. On the shm branch `scripts/shm-up.sh` takes the
same variables and prints the same knobs (its hwdec tag defaults to
`shmhwdec`, built FROM `heco-ingest:shm`, like `:shmcuda`).

Images the overlays need, built from THIS tree's plain images:

    ./scripts/build-images.sh      # heco-*:latest, heco-{persons,faces,embed}:cuda — WITHOUT TensorRT
    HECO_TRT=1 ./scripts/build-images.sh   # the same, :cuda WITH TensorRT (WITH_TENSORRT=1, +8 GB an image)
    docker build -f docker/ingest-hwdec.Dockerfile --build-arg BASE=heco-ingest \
      -t heco-ingest:hwdec .       # never via compose build with the overlay

A lever changes a running stack only on recreate (`up -d` recreates what
changed). Check `status` after every change: a knob that did not reach its
container is the failure this repo keeps finding.

## Rollout order

1. **match** first whenever its wire changes. 0.14.0 accepts `head` /
   `beard` on `/match` (an older match ignores them, so the order is not
   load-bearing for correctness) and logs the per-sighting evidence the
   clothing, head and beard set-asides read — a run made before match is
   deployed has no body-log evidence and falls back to templates for
   clothing, and has no head or beard evidence at all.
2. **persons / faces / embed**: rebuild `:cuda` (and `:shmcuda`) WITH
   TensorRT — `HECO_TRT=1 ./scripts/build-images.sh`; a plain build has been
   TensorRT-free since f1b2f07 and `HECO_TRT=1 demo-up` on it runs CUDA fp32
   (/health says so: no TensorRT in `active`, `trt` null) — before adding
   `docker-compose.trt.yml`; boot one
   stack first and let it build its engines (YOLOX-s alone is ~157 s — longer
   than the console's ~94 s apply envelope, so warm every model before the
   event). Changing `FACES_SCRFD_INPUT` or a model later is a cold build.
3. **ingest** before the runner: the runner forwards `source.motionGate` /
   `source.bufferS` to ingest `/open`, and an ingest from before the levers
   drops them (nothing engages). With every lever off the new ingest is
   today's worker.
4. **runner** last among the services; `pipeline.json` declares
   `capabilities.faceRegion: true`, which is what makes the console forward
   a region at all.
5. **console** (heco-site-planner) at any point: it degrades cleanly against
   an older gallery or runner. Its node server only reloads on restart —
   restart it to get the `setAside` pass-through and `faceRegion`
   forwarding; the vite frontend hot-reloads on its own.

Rollback of every lever is an unset variable (or a dropped `-f`) and a
recreate.

## What is still unmeasured, and what to measure at the pre-test

* End-to-end fps with levers on, on the box, both cameras: run
  `scripts/bench-live.py` against the real console (it was tested only
  against a fake) with the recommended set — `INGEST_DECODER=nvdec
  INGEST_CV_THREADS=1 INGEST_LIVE_TIMEOUT_S=10`, TensorRT with
  `FACES_SCRFD_INPUT=1472x832`, `HECO_PIPELINE_OVERLAP=1
  HECO_PARALLEL_DETECT=1` (`HECO_APPEARANCE_WB=1` only where the light changes) — and
  compare unique counts against a lever-off run of the same clip, not just
  fps. `bench-live.py` on a paced run: read `framesDroppedLive` beside its
  verdict.
* The review under the event's own light: after a run, open the "Set
  aside" list and check it for a genuine duplicate. The light guard is off
  in `demo-up.sh` (fixed chandelier light); at a venue with stage washes,
  start with `HECO_REVIEW_LIGHT_TOL=0.07` and read `keptByLight`.
* **GPU clock state.** Under one-request-at-a-time load WDDM keeps the 4060
  at P8/P5 (210–495 MHz): persons `session.run` 46 ms there against 6.5 ms
  clocked up. Every stage is 3–7x slower than its standalone number until
  someone with Windows admin sets "Prefer maximum performance" (or
  `nvidia-smi -lgc 2400,2900` elevated). Check during a run with
  `/usr/lib/wsl/lib/nvidia-smi --query-gpu=pstate,clocks.gr --format=csv -lms 250`.
* The motion gate: leave it OFF on the Sharon placement (it skips nothing
  there at the default); calibrate other placements with `gate_replay.py`.
* The face region: not a recall superset — two real guests were lost on the
  Sharon frames. The cadence: needs `HECO_FACE_REVERIFY_INTERVAL_S` 2–3 s,
  unmeasured on real footage.

## Known gaps

* The runner stamps `devices` from persons alone, at run start: ingest's
  decoder truth (`active` is known only once a capture is open) and the
  faces / embed TensorRT truth are not in the run record, so the console
  says "nvdec requested — what actually ran was not recorded".
* Pre-existing, default path: in today's lockstep loop ingest reads
  `worker.ended` after the 14–21 ms JPEG encode, so the LAST frame of a
  lockstep file run usually goes out with `ended=true` and is dropped. Lever
  mode decides `ended` atomically and does not have this bug.
* ruff: 11 findings on main that predate every lever (persons
  `app/model.py`, `app/__init__.py`; faces `app/detector.py`, `app/scrfd.py`).
